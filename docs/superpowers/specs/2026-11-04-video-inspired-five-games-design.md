# Joybit 视频启发的五款关卡游戏设计

## 目的与用户决定

参考 [B 站视频 BV1yr4y1Q714](https://www.bilibili.com/video/BV1yr4y1Q714/) 的玩法机制，为 Joybit 新增五款独立、原创的手机小游戏：六角拼块、物理吃星星、滚球躲障碍、限时做菜和场景找物。用户从视频中确认选择这五类，并要求每款有不同难度、至少 100 关，或在可行时持续生成无限关卡。使用原创名称、规则细节和代码绘制的画面，不复用视频中游戏的素材、角色、关卡或品牌。

## 关卡方案与取舍

1. **逐关手工设计**：易于精雕早期体验，但五款共 500 关，制作和校验成本高，后续扩展慢。
2. **完全即时随机**：实现入口快，但容易出现无解、无聊或忽高忽低的关卡，也无法稳定重玩同一关。
3. **按编号和固定种子生成（推荐）**：每款至少实现 1–100 关，随编号递进并可继续生成 101 关以后；关卡内容可重现，生成器对可玩性作约束或验证。物理关卡采用受控模板和模拟检查，不能把随机摆放当成可解关卡。

采用方案 3。它满足用户对 100 关和长期持续游玩的两个目标。若某款生成器无法在给定种子下形成合法关卡，应确定性地选择后备模板，不能展示坏关。无限关卡指编号上可持续生成并在合理难度上限后继续变化，不宣称难度数学上无限增长。

## 五款玩法

| 游戏 | 单关目标与操作 | 难度递进 | 生成与验收约束 |
| --- | --- | --- | --- |
| 六角拼块 | 从候选块中选择并放入六角网格，填满指定线或区域以达到目标分数；无合法落点时失败，可重开本关。 | 网格障碍、块形、目标分数和可用步数逐渐变化。 | 从有限块库和合法放置路径反向构造，再用搜索确认至少存在一条通关序列。 |
| 星星轨道 | 点击机关改变挡板/斜坡，让小球沿重力路径收集星星并到达出口；可暂停和重开。 | 星星数、机关数、路径分支和时机窗口逐渐增加。 | 组合可解的房间模板，用与游戏一致的简化物理模拟或状态搜索验证可通关；过不了验证即换模板。 |
| 滚球躲障碍 | 横向滑动切换三条跑道，在终点前避开障碍并收集目标数量的光点。 | 距离、速度、障碍密度和安全路线切换频率增加；速度有上限。 | 逐段先建立安全路线，再布置其他障碍；验证每段之间有足够的反应时间和可达的安全车道。 |
| 街角小厨 | 按顾客订单点击食材和步骤，按正确顺序完成菜品，在倒计时内交付指定订单数。 | 食材、步骤、并发订单和时间压力逐渐增加；设置合理上限。 | 从配方规则组合订单，保证所需食材均可见、订单可在规定时间内完成。 |
| 寻物小屋 | 在原创绘制场景中找出目标物，点中后标记；找齐过关。提供有限提示。 | 场景物件数、相近形状干扰、目标数和计时要求逐渐增加。 | 使用矢量物件库和有界布局，保证目标完整可见、有足够触控面积、没有目标互相遮挡。 |

五款均提供关卡号、目标、开始或暂停、胜负反馈、重试和下一关。前几关承担教学作用；后续不能仅通过缩小触控目标或无限加速制造难度。失败后可立即重试同一固定关卡。适配竖屏手机和触控，保留可读文字、形状与颜色的双重提示。

## Joybit 接入

- 延续现有 `src/miniGames` 离线 HTML/WebView 机制，游戏画面由项目代码绘制，不下载远程素材。首页每款一张独立封面卡片，沿用现有登录门槛、返回、收藏和七种语言。
- 新增通用的关卡编号、种子与进度记录。按账号 ID 和游戏 ID 在设备本地保存最高解锁关卡及生成器版本；WebView 只收到关卡配置，不收到账号令牌。完成消息仅更新本地进度，不涉及云端奖励或排行榜。
- 关卡生成器与规则尽量独立于画面，便于对 1–100 关和更高编号做批量验证。暂停、退出和重入时清理计时器及动画；再次进入可选已解锁关卡。
- 用现有七种语言展示游戏名、操作说明、关卡与结果文字。数字与图形保持跨语言一致。优先 iOS，沿用 React Native WebView 的 Android 兼容路径。

## 范围边界

本轮交付五款可玩的独立游戏、前 100 关的确定性生成与继续生成能力、基础进度保存、首页入口和必要验证。不开启付费、广告奖励、云端分数或真实游玩人数。视频内容仅作玩法参考；画面和关卡均独立制作。

## 验收

1. 五张新卡片可从首页分别进入；未登录先走现有登录流程，已登录设备断网后仍可游玩和返回。
2. 每款 1–100 关均能按关卡号稳定重现，核心规则验证通过；101 关及更高编号仍能生成合法关卡。物理和六角关卡的可解性通过与实际规则一致的验证器检查。
3. 难度在若干关卡区间按可量化参数递进，且存在上限以保持可玩性；通关解锁下一关，退出后进度可恢复，不串到其他账号。
4. 竖屏常见尺寸中触控目标、文字和结果清楚；各游戏能正常重试、暂停、退出与重入。七种语言的名称和关键操作文案齐全。
5. 运行项目已有单元/UI 测试及类型检查；在可用的模拟器或真机上检查五款游戏的实际触控流程。无法做的设备验证必须单独标明。
