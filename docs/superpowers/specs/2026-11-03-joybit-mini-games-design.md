# Joybit 首批内置小游戏设计

## 目的与范围

在现有 Hexa Landing 之外增加三款真正可玩的小游戏，让首页双列目录有内容。用户已选择新做游戏，而非接入其他现有仓库；选择内置离线网页游戏，首批内容为反应挑战、记忆翻牌、数字拼图。Joybit 先支持 iOS，小游戏页面保留 Android 复用能力。

邮件、云端分数、真实游玩人数和广告接入不属于本轮。所有游戏都要求先登录 Joybit。三款新游戏可在已登录后离线运行：首次登录仍需网络；设备上已有本地登录会话时，即使暂时断网，也能进入这三款不访问服务器的游戏。用户主动退出登录后不能进入。离线时无法确认服务端撤销状态，联网后按现有账号流程重新校验。收藏沿用现有机制，不为小游戏新增后台接口。

## 玩法与界面

- **反应挑战**：点击开始后随机等待，变色后立即点击。提前点击记为抢跑，可重新开始；完成 5 次有效反应后显示平均反应时间与最佳单次成绩。等待、反应、结果状态有明确文字和颜色区分。
- **记忆翻牌**：4×4、8 对图案。每次翻两张，不匹配则短暂展示后盖回；记录翻牌次数与用时。全部配对后显示结果并可重玩。
- **数字拼图**：3×3 的 1–8 数字与一个空格。通过合法移动打乱，确保每局可解；点击空格相邻数字移动；完成后显示步数和用时，可重新开始。
- 三款游戏都采用触控友好的大按钮、清晰的开始/重玩入口和 Joybit 顶部返回按钮；已登录设备在竖屏、无网络时可完整游玩。运行中的计时器在退出页面时停止。游戏内容本身不请求登录或网络，也不接收 Supabase 会话。
- 首页增加三张独立封面卡片，沿用双列布局、名称、收藏按钮。没有真实统计来源时不显示“玩过人数”。

## 接入方案

**已选择：内置离线网页游戏。** 将每款游戏的 HTML、CSS、JavaScript 打包在 Joybit 内，由现有 WebView 加载静态 HTML。游戏内容无远程脚本和资源，可在 iOS 先运行，并保留 Android 复用路径。修改游戏入口：未登录时跳转现有登录界面；三款离线游戏在已有本地会话时直接打开，避免每次进入都依赖网络校验；原生游戏仍使用在线有效会话校验。WebView 中的游戏代码不接收账号令牌。

比较过的另一方案是用 React Native 组件实现游戏，触感更接近原生界面，但三套玩法需要跨端界面和动画适配，开发与维护量更大。远程网页方案易更新，但依赖网络；与本轮离线游玩目标不符。

## 验收

首页准确显示 4 款可打开的游戏。未登录用户点击任一游戏时先进入登录；已有本地登录会话的用户即使断网，也可进入、完成并重玩三款新游戏；Hexa Landing 仍走现有在线会话校验。三款游戏离线运行、无虚构人数，关闭后可返回目录，收藏按钮与游戏入口互不触发。自动测试覆盖目录、登录入口路由和各玩法的核心规则；在 iOS 模拟器检查布局与触控流程。
